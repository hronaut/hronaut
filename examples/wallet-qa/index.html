Hronaut local wallet QA

This fixture uses the injected EIP-1193 provider for wallet operations and direct local JSON-RPC only for authoritative readback.

Its event log correlates each attempt without recording account addresses, transaction hashes, signing payloads, signatures, provider error messages, or RPC URLs. A JavaScript provider call leaves wallet dispatch, approval, broadcast, and confirmation unknown until stronger evidence exists.

Provider and session

Sign-in

Builds a Sign-In with Ethereum (EIP-4361) message for this page's origin, the first connected account, and the current chain, then asks the wallet to sign it with personal_sign and checks with personal_ecRecover that the connected account signed it, as a website's sign-in backend would. Connect first with Request accounts.

Token permit

Builds an EIP-2612 token permit as EIP-712 typed data for the first connected account and the current chain, then asks the wallet to sign it with eth_signTypedData_v4. The permit lets a fixed test spender move 1,000,000 of a token's smallest units from a fixed test token address for one hour. Nothing is sent on chain. Hronaut shows the spender, amount and warnings under Typed data to sign, and a person always approves typed data.

Add token

Offers the same fixed test token to the wallet with wallet_watchAsset (EIP-747), the way a dApp's "Add token to wallet" button does. Hronaut accepts the offer without a dialog. Like MetaMask, it refuses it with code -32602 when the symbol or decimals disagree with what the token contract reports.
